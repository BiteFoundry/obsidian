## Changes

This release closes security gaps in `serve` and the MCP server, fixes Korean/CJK search misses, and repairs several cases where notes, settings or index rows were lost or misnamed.

### Security

- `serve` and the MCP server accept a per-request `vault` only when it is the vault the server was started with, or a registered or auto-discovered vault. Before, any directory could be named, and it was scanned and served.
- `serve` requires a Bearer token on `/api/v1/*`. Without `--token` it generates a random 32-byte token for the run and prints it once on stderr. It checks the `Host` and `Origin` headers on every route, sends no CORS headers unless an origin is listed with `--allow-origin`, and refuses a non-loopback `--bind` without `--token`.
- On Windows, a note path can no longer leave the vault through a drive prefix or a stream separator (`C:...`, `name:stream`).

### Fixes

- **Search**: a Korean, Japanese or Chinese query of three or more characters finds words that contain it (`회의록` finds `주간회의록`).
- **UNC vaults**: a vault on `\\server\share\...` opens.
- **Index**: a folder that cannot be read (permissions, I/O error) keeps its notes and bookmarks in the index. A sync after a small change re-resolves only the links that can have changed, not every link in the vault.
- **Watcher**: a note that was locked while it was being saved is still retried after another note syncs in between.
- **Config**: a `config.toml` that cannot be parsed is never overwritten. `vaults add`, `vaults use`, `vaults remove` and `init` stop with an error; other commands run on defaults with a warning.
- **Daily notes**: the folder and file name follow `.obsidian/daily-notes.json`. `"folder": ""` means the vault root, and formats such as `YYYY-MM-DD dddd` or `YYYY-MMM-DD` give the file name Obsidian uses.
- **TUI**: collapsing a folder hides its subfolders. Opening a note no longer creates an empty note when the reference is ambiguous, missing or unreadable; only following an unresolved link creates one.
- **MCP**: the descriptions of `reindex_vault`, `list_vaults`, `find_orphans`, `get_local_graph` and `list_tags` say that they work over the whole vault.

## Compatibility

- HTTP clients must send `Authorization: Bearer <token>` on `/api/v1/*`. Pass `--token <value>` to keep a fixed token, read the generated one from stderr, or pass `--allow-keyless` to serve a loopback address without a token as before. `/health` needs no token.
- Web pages on other origins no longer get CORS access. Start the server with `--allow-origin https://your.app` (exact origin, repeatable; `--cors-origin` is an alias). Clients that reach the server by a LAN address or host name other than the `--bind` address need `--allow-host <host>`.
- `serve --bind 0.0.0.0` (any non-loopback address) without `--token` refuses to start.
- A `vault` argument naming an unregistered directory returns `vault_not_found` (HTTP 404). Register the directory first with `bitefoundry-obsidian vaults add <path>`.
- On Windows, a note path containing `:` is rejected with `invalid_argument`. File names with `:` keep working on Linux and macOS.
- Daily notes: a vault with `"folder": ""` gets new daily notes at the vault root, and a vault whose format uses `MMM`, `MMMM`, `ddd`, `dddd`, `D`, `M` or `[text]` gets differently named files than before. Daily notes created earlier are not moved or renamed. Month and weekday names are always English.
- The `auto_daemon`, `density` and `notify` settings and the `OBSIDIAN_AUTO_DAEMON` variable had no effect and are removed. Config files that still contain these keys load as before.
- Sync and reindex statistics gain an `unreadable_dirs` count when a folder could not be read.
